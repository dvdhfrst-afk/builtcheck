# Languages and alternate versions

Language tags in `lang` attributes, and the `hreflang` annotations that tell search engines which pages are versions of each other in other languages. Annotations are read from `link rel="alternate" hreflang` elements in pages and from `xhtml:link` elements in the sitemap, and both are held to the same checks. An `hreflang` on an `a` element is only a hint about its target, and one on a link with a `type` other than `text/html`, such as a feed, says what language that file is in, so neither is read.

| Rule | Default | Reports |
|---|---|---|
| `i18n/lang-invalid` | error | A `lang` attribute, on `html` or any other element, is not a valid language tag. An empty `lang` means the language is unknown, which is allowed. |
| `i18n/hreflang-invalid` | error | An `hreflang` value in a page or the sitemap is not a valid language tag or `x-default`. |
| `i18n/hreflang-duplicate` | error | The same `hreflang` value appears twice in one set of alternates, ignoring case. |
| `i18n/hreflang-self` | warning | A page, or a sitemap entry, lists other language versions but not itself. |
| `i18n/hreflang-target` | error | An alternate names a page that is not in the build, redirects, asks not to be indexed, is an error page or names a different page as its canonical. In the sitemap, an alternate that is not an absolute URL counts too. |
| `i18n/hreflang-reciprocal` | error | A language version named as an alternate does not name this page back, so search engines ignore the pair. In the sitemap, a version with no entry of its own counts too. |
| `i18n/x-default` | warning | An `x-default` alternate is given without any language versions, or the versions of a page name different `x-default` pages. |
| `i18n/lang-mismatch` | warning | A page's `lang` names a different language from the `hreflang` its versions, or the sitemap, give it. |

Options:

- `i18n/lang-invalid` and `i18n/hreflang-invalid`: `languages` lists extra language codes to accept, for a language the built-in list does not hold.

A language tag is checked against the syntax of BCP 47 (the standard for language tags) and against built-in lists: every ISO 639-1 two-letter language code and every ISO 3166-1 country code. Codes that are often written by mistake get a hint: `jp` for `ja`, `en_US` for `en-US`, `en-UK` for `en-GB`, and three-letter codes such as `eng` that have a two-letter form. Other three-letter language codes are accepted, since the full list of them runs to thousands. In `hreflang`, a private use tag such as `x-mine` is reported, since `x-default` is the only one search engines know.

Only indexable pages are held to the checks that compare pages: a page that asks not to be indexed has its annotations ignored by search engines anyway. An alternate on another host cannot be checked against the build and is left alone. When the site host is not known, from `site.url`, the sitemap or the canonical links, an absolute URL may be this site, so those checks say nothing. An entry naming the page's own canonical URL counts as naming itself. Languages that share a code, such as `no` and `nb`, or `zh` and `yue`, are not a mismatch, and neither is a region: `lang="en"` matches `hreflang="en-GB"`. An `x-default` often names a language chooser, so it does not need to link back.

Every entry in a sitemap group repeats the same alternates, so one mistake there is reported once, at its first place, with how many places it recurs. When `links/broken-internal` is on, it reports an alternate link in a page that names a missing file, so that is reported once.
